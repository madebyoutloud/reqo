# @outloud/reqo

## Recommended defaults

- Reuse the project's client. Create one per API with `createClient({ url, headers })` at app setup, never inside a component or a loop.
- When rendering on the server, the client must act as the user: create it per request with that request's `cookie` header, and no other header, and never share it between requests.
- Keep authentication, shared headers and error mapping in client hooks, not in each call.
- Every method takes `(url, options)`. The body goes in `data`, query values in `query`, and `params` fills `{name}` placeholders in the URL.
- Use the `$` methods (`$get`, `$post`, `$put`, `$patch`, `$delete`) for the response data. Use the plain ones (`get`, `head`, `post`, `put`, `patch`, `delete`) when you need the status or headers: they return the `Response` with `.data`.
- Type the data: `api.$get<User[]>(...)`. With an OpenAPI schema generated by openapi-typescript, use `createSchemaClient<paths>()`, which types URLs, parameters, bodies and responses.
- Catch errors only where you handle them, narrow with `api.isError(error)`, and rethrow the rest.

```ts
const users = await api.$get<User[]>('/users', { query: { status: 'active' } })
const user = await api.$post<User>('/users', { data: payload })
await api.$patch('/users/{id}', { params: { id }, data: changes })
await api.$delete('/users/{id}', { params: { id } })
```

Query values are serialized for you: `null` and `undefined` are skipped, arrays become `id[]=1&id[]=2`, and objects become `filters[name]=John`.

## Valid alternatives

- `reqo`, the client the package exports, for one-off requests to absolute URLs in scripts.
- `responseType: 'json' | 'text' | 'blob' | 'arrayBuffer'` when `auto` is wrong. `auto` reads JSON for a JSON content type, text for plain text or no content type, and nothing for any other type. `false` doesn't read the body.
- A `validate(response)` client option, when an API answers successfully with a status outside 2xx.
- `api.request({ method: 'OPTIONS', url })` for a method without a shortcut.
- `FormData`, `URLSearchParams`, `Blob` or a stream in `data`: they are sent as they are. Objects are sent as JSON.

## Avoid by default

- Retrying writes. Retries are off unless you pass `retry`. Then only `GET`, `HEAD` and `OPTIONS` retry, on transient status codes and network errors. Add `methods: ['POST']` only when the endpoint is idempotent.
- Retries without `totalTimeout` on requests a user waits for. `timeout`, 60 seconds by default, applies to each attempt.
- Logging the error object. `error.config` holds the request headers, credentials included. Log `error.toJSON()`, which leaves headers out but keeps the URL, `params`, `query` and the response `data`.
- Building query strings or putting values into the path by hand.

## Invalid patterns

- A body or query as the second argument, such as `api.$post(url, body)` or `api.$get(url, query)`. The second argument is always the options, and a body there is often read as options without a type error.
- `params` for query values. It only fills `{name}` placeholders.
- `$head`. It doesn't exist; use `head` and read the response.
- `error.url`, `error.method` or `error.params`. They don't exist; read `error.config.url`, `error.config.method` and `error.config.query`.

## Recipes

### Handling an error

```ts
try {
  return await api.$post<User>('/users', { data: payload })
} catch (error) {
  if (!api.isError(error) || error.status !== 422) {
    throw error
  }

  return showValidationErrors(error.data)
}
```

A `RequestError` has `status` (-1 without a response), `code` (`E_TIMEOUT`, `E_CANCELED`, a network code such as `ECONNREFUSED`, or empty), `data`, `response`, `config` and `toJSON()`.

### Mapping errors in one place

```ts
api.on('error', (error) => {
  if (error.status === 401) {
    return new SessionExpiredError()
  }
})
```

A hook that returns an error replaces the thrown one. Returning nothing keeps it.

### Retries and timeouts

```ts
const report = await api.$get('/reports/{id}', {
  params: { id },
  retry: { limit: 3 },
  timeout: 10_000,
  totalTimeout: 30_000,
})
```

### Cancellation

Every call returns a cancellable promise: keep it and call `request.cancel()`, or pass `signal`. A `signal` in the client options aborts all of its requests. A canceled request rejects with `code` `E_CANCELED`.
