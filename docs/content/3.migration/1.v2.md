---
title: v1 to v2
description: Breaking changes introduced in version 2.0.0 and how to upgrade.
---

Version 2.0.0 reworks the request signature, splits query and path parameters, and adds the [Schema Client](/guide/schema-client).

## Request Arguments

All method shortcuts now take exactly two arguments: `url` and `options`. The request body, query parameters and path parameters are passed through `options` as `data`, `query` and `params`.

:::code-group
```ts [v2]
await reqo.get('/users', { query: { limit: 10 } })
await reqo.$get('/users', { query: { limit: 10 }, timeout: 5000 })

await reqo.post('/users', { data: { name: 'John' } })
await reqo.$post('/users', { data: { name: 'John' }, timeout: 5000 })
```

```ts [v1]
await reqo.get('/users', { limit: 10 })
await reqo.$get('/users', { limit: 10 }, { timeout: 5000 })

await reqo.post('/users', { name: 'John' })
await reqo.$post('/users', { name: 'John' }, { timeout: 5000 })
```
:::

::warning
The v1 call `reqo.$post('/users', body)` is still valid TypeScript in v2, but `body` is now interpreted as the options object. Every `post`, `put` and `patch` call has to be updated, the compiler will not always catch it.
::

## Query and Path Parameters

`params` used to hold the query string values. It now holds path parameters, which replace `{name}` placeholders in the URL. Query string values moved to `query`.

:::code-group
```ts [v2]
await reqo.$get('/users/{id}', {
  params: { id: 123 },
  query: { include: 'profile' }
})
// GET /users/123?include=profile
```

```ts [v1]
await reqo.$get(`/users/${id}`, { include: 'profile' })
// GET /users/123?include=profile
```
:::

::note
Rename every `params` option that carried query values to `query`. This also applies to the client-level `request` method.
::

## Head Shortcut

`$head` was removed, since a HEAD response has no body. Use `head` and read the response metadata.

```ts
const response = await reqo.head('/users')
console.log(response.status)
```

## Error Properties

`RequestError` no longer copies request details onto the error instance. Read them from `error.config` instead.

| v1 | v2 |
| --- | --- |
| `error.url` | `error.config.url` |
| `error.method` | `error.config.method` |
| `error.params` | `error.config.query` (or `error.config.params` for path parameters) |
| `error.client` | `error.config.id` |

`error.status`, `error.code`, `error.data`, `error.request`, `error.response` and `error.toJSON()` are unchanged. `toJSON()` now reports both `params` and `query`.

## Exports

The package no longer re-exports everything from `client.js`. The public exports are:

```ts
import {
  reqo,             // default client instance
  createClient,
  createSchemaClient,
  Client,
  SchemaClient,
  BaseClient,
  errors
} from '@outloud/reqo'

import type {
  ClientOptions,
  RequestConfig,
  RequestOptions,
  RequestMethod,
  RequestState,
  Response
} from '@outloud/reqo'
```

Notable changes:

- `http` was removed, use `reqo`.
- `ClientOptions` moved from `client.js` to the types module, it is still exported from the package root.
- `Params` and `HeaderValues` were merged into a single internal `Values` type (`Record<string, any>`).
- The `Hooks` interface was renamed to `HookList`. `Hooks` is now the class that implements `on`, `off` and hook execution, and `BaseClient` extends it.
- `BaseClient` is exported and holds the request logic. `Client` adds the method shortcuts on top of it.

## New: Schema Client

`createSchemaClient` types requests from an OpenAPI schema generated with [openapi-typescript](https://openapi-ts.dev/):

```ts
import { createSchemaClient } from '@outloud/reqo'
import type { paths } from './api.js'

const api = createSchemaClient<paths>({ url: 'https://api.example.com' })

const event = await api.$get('/special-events/{eventId}', {
  params: { eventId: '123' }
})
```

See the [Schema Client](/guide/schema-client) guide for details.
