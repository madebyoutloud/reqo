---
title: v2 to v3
description: Breaking changes introduced in version 3.0.0 and how to upgrade.
---

Version 3.0.0 merges `Client` and `SchemaClient` into one [typed `Client<Paths>`](/guide/schema-client), adds [plugins](/guide/instances#plugins) and client identity (`name`, `meta`), and reworks errors: every error has a [`kind`](/guide/error-handling#error-kinds) and a code, and [`toJSON()`](/guide/error-handling#logging-errors) returns a summary without headers and bodies. Requests return reqo's own [`RequestPromise`](/guide/basic-usage#cancellation), with `safe()`.

## Status Without a Response

`error.status` is `undefined` when no response was received, instead of `-1`.

:::code-group
```ts [v3]
if (error.kind === 'network') showOffline()
if ((error.status ?? 0) >= 500) retryLater()
```

```ts [v2]
if (error.status === -1) showOffline()
if (error.status >= 500) retryLater()
```
:::

## Error Codes

Every error has a code: `E_HTTP` for a failed status and `E_NETWORK` for a network error without a code, both empty before. Two new kinds have their own code: `E_PARSE` for a successful response whose body doesn't parse, and `E_INVALID_REQUEST` for a request that can't be built, e.g. a missing path parameter, which now rejects with its own message instead of "Request failed due to a network error.".

:::code-group
```ts [v3]
if (error.kind === 'http') showServerError(error.status)
```

```ts [v2]
if (!error.code) showServerError(error.status)
```
:::

## Serialized Errors

`error.toJSON()` returns the client `id` and `name`, the method, the full URL with path parameters and query, the path parameters, `status`, `kind`, `code`, `message`, `duration` and `attempts`. It no longer includes `query` and the response `data`; read them from `error.config.query` and `error.data`.

## Binary Responses

With the default `responseType: 'auto'`, a response whose content type is neither JSON nor text, e.g. a PDF, resolves to a `Blob` instead of `undefined`. Pass `responseType: false` to keep not reading the body.

## Timeout and Request Hooks

The per-attempt `timeout` starts after the `request` hooks, so a hook that waits, e.g. the new [`rateLimit`](/guide/instances#rate-limiting) plugin, doesn't use it up. `totalTimeout` still counts the wait. Hooks get `state.signal`, to stop waiting when the request is aborted.

## Request Promise

Requests return a `RequestPromise` instead of a `Future` from `@outloud/future`, which reqo no longer depends on. It has `cancel(reason?)`, `timeout(ms)` and `safe()`. `result()` is a deprecated alias of `safe()`, and `timeout(ms)` now rejects with a `TimeoutError` instead of a `CanceledError`. `then`, `catch` and `finally` return a plain `Promise`, so cancel the original request:

:::code-group
```ts [v3]
const request = api.$get<User[]>('/users')
const names = request.then((users) => users.map((user) => user.name))
request.cancel()

const [users, error] = await api.$get<User[]>('/users').safe()
```

```ts [v2]
const names = api.$get<User[]>('/users').then((users) => users.map((user) => user.name))
names.cancel()

const [users, error] = await api.$get<User[]>('/users').result()
```
:::

## Headers

`headers`, of the client and of a request, also accept a `Headers` instance and `[name, value]` entries, which were dropped before. Request headers override client headers whatever the case of the name: a client `Authorization` and a request `authorization` send the request's value, the client's was sent before.

## Form Bodies

An object sent with `content-type: application/x-www-form-urlencoded` is encoded as a form, e.g. `name=a+b&tags%5B%5D=x`, instead of `name,a b,tags[],x`.

## Schema Client

`createSchemaClient<paths>()` and `SchemaClient<paths>` still work, as deprecated aliases of `createClient<paths>()` and `Client<paths>`.

:::code-group
```ts [v3]
const api = createClient<paths>({ url })
class MuseumApi extends Client<paths> {}
```

```ts [v2]
const api = createSchemaClient<paths>({ url })
class MuseumApi extends SchemaClient<paths> {}
```
:::
