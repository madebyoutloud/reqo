The library provides a simple and intuitive API for making HTTP requests. You can use the default `reqo` instance or create custom clients for different configurations, see more in the [Instances](/guide/instances).

## Making Requests

```ts
import { reqo } from '@outloud/reqo'

// Get response with data
const response = await reqo.request({
  url: 'https://api.example.com/users',
  query: { limit: 10 }
})
console.log(response.data)

// Using method shortcuts
const users = await reqo.get('https://api.example.com/users', { query: { limit: 10 } })
console.log(users.data)

// Get data directly using $ prefix
const usersData = await reqo.$get('/users')
console.log(usersData)

// Type the response
interface User {
  id: number
  name: string
  email: string
}

const typedData = await reqo.$get<User[]>('/users')
console.log(typedData) // User[]
```

## Method shortcuts
All HTTP methods have corresponding shortcuts and `$` variants for direct `data` access.

::note
Every shortcut accepts the same two arguments: `url` and an `options` object. Body, query parameters and path parameters are all passed through `options` as `data`, `query` and `params`.
::

```ts
reqo.get(url, options?)
reqo.head(url, options?)
reqo.post(url, options?)
reqo.put(url, options?)
reqo.patch(url, options?)
reqo.delete(url, options?)

// $ variants return `response.data` instead of the response
reqo.$get(url, options?)
reqo.$post(url, options?)
reqo.$put(url, options?)
reqo.$patch(url, options?)
reqo.$delete(url, options?)
```

::warning
`head` has no `$head` variant, since a HEAD response has no body.
::

```ts
// GET with query parameters
const response = await reqo.get('/endpoint', {
  query: { param1: 'value1' },
  timeout: 3000
})

// data is the same as response.data
const data = await reqo.$get('/endpoint', {
  query: { param1: 'value1' },
  timeout: 3000
})

// POST with a body
const created = await reqo.$post('/endpoint', {
  data: { key: 'value' }
})

// DELETE
await reqo.$delete('/endpoint/{id}', {
  params: { id: 1 }
})
```

### Options
All request methods accept an options object. The `request` method accepts the same options plus `url` and `method`:

```ts
const response = await reqo.request({
  // Request URL
  url: 'https://api.example.com/data/{id}',

  // HTTP method
  method: 'POST',

  // Path parameters, replaces `{id}` placeholders in the URL
  params: { id: 42 },

  // Query parameters
  query: { q: 'search' },

  // Custom headers
  headers: {
    'Authorization': 'Bearer token',
    'X-Custom-Header': 'value'
  },

  // Request body
  data: { key: 'value' },

  // Timeout in milliseconds
  timeout: 5000,

  // Retry configuration
  retry: {
    limit: 3,
    delay: (state) => state.retryCount * 1000
  },

  // Response type
  responseType: 'json',

  // Abort signal for cancellation
  signal: controller.signal,

  // Redirect behavior
  redirect: 'follow',

  // Credentials
  credentials: 'include',

  // Mode
  mode: 'cors'
})
```

## Path Parameters
Use the `params` option to fill `{name}` placeholders in the URL. Placeholders without a matching value are replaced with an empty string.

```ts
const post = await reqo.$get('/posts/{id}', {
  params: { id: 123 }
})
// GET /posts/123

const comment = await reqo.$get('/posts/{postId}/comments/{commentId}', {
  params: { postId: 123, commentId: 5 }
})
// GET /posts/123/comments/5
```

## Query Parameters
Use the `query` option to send query parameters, it will be serialized automatically.

```ts
// Single values
const users = await reqo.$get('/users', { query: { id: 123 } })
// GET /users?id=123

// Arrays
const filtered = await reqo.$get('/users', {
  query: {
    id: [1, 2, 3],
    status: 'active'
  }
})
// GET /users?id[]=1&id[]=2&id[]=3&status=active

// Nested objects
const results = await reqo.$get('/search', {
  query: {
    filters: { name: 'John', age: 30 }
  }
})
// GET /search?filters[name]=John&filters[age]=30

// POST with query params
const user = await reqo.$post('/users', {
  data: { name: 'Jane' },
  query: { ref: 'newsletter' }
})
// POST /users?ref=newsletter
```

::note
`null` and `undefined` values are skipped during serialization.
::

## Request Body
Pass the request body in the `data` option.

::tip
Different body types are automatically detected and serialized.
::

```ts
// JSON body (automatically serialized)
await reqo.$post('/users', {
  data: {
    name: 'John',
    email: 'john@example.com'
  }
})

// FormData
const formData = new FormData()
formData.append('file', file)
formData.append('name', 'Document')
await reqo.$post('/upload', { data: formData })

// URLSearchParams (sent as application/x-www-form-urlencoded)
const params = new URLSearchParams()
params.append('key', 'value')
await reqo.$post('/form', { data: params })

// Plain object as url-encoded (set content-type header)
await reqo.$post('/form', {
  data: { key: 'value' },
  headers: { 'Content-Type': 'application/x-www-form-urlencoded' }
})
```

## Response Type
The response body is automatically parsed based on the `Content-Type` header by default. You can also explicitly set the expected response type using the `responseType` option.

```ts
// Automatically parsed as JSON if Content-Type is application/json, otherwise returns text, this is default behavior
const data = await reqo.$get('/data', {
  responseType: 'auto'
})

// JSON
const json = await reqo.$get('/data', {
  responseType: 'json'
})
console.log(json) // JSON object

// Plain text
const text = await reqo.$get('/file.txt', {
  responseType: 'text'
})
console.log(text) // string

// Binary data
const blob = await reqo.$get('/image.png', {
  responseType: 'blob'
})
console.log(blob) // Blob

// Array buffer
const buffer = await reqo.$get('/binary', {
  responseType: 'arrayBuffer'
})
console.log(buffer) // ArrayBuffer

// No parsing
const response = await reqo.get('/endpoint', {
  responseType: false
})
// Process body manually
const reader = response.body?.getReader()
```

## Working with Responses
When using methods without `$` prefix, you get the full `Response` object.

```ts
const response = await reqo.get('/users')

// Access response data
console.log(response.data)

// Response metadata
console.log(response.status)
console.log(response.statusText)
console.log(response.headers)
console.log(response.ok)

// Check content type
const contentType = response.headers.get('content-type')
```

The `$` prefix methods return only the data:

```ts
// Returns the data directly
const users = await reqo.$get('/users')

// Equivalent to:
const response = await reqo.get('/users')
const users = response.data
```

## Timeouts
Set request timeouts to prevent hanging requests.

::warning
The default timeout is 60 seconds. You can change it globally in the client options or per request using the `timeout` option.
::

```ts
try {
  // 5 second timeout
  const data = await reqo.$get('/slow-endpoint', {
    timeout: 5000
  })
} catch (error) {
  if (reqo.isError(error) && error.code === 'E_TIMEOUT') {
    console.log('Request timed out')
  }
}
```

## Cancellation
Requests return a cancellable Future (extended Promise). You can cancel requests using the Future's `cancel` method or an `AbortController`.

### Cancel method
```ts
// Start request
const request = reqo.get('/users')

// Cancel after 1 second
setTimeout(() => request.cancel(), 1000)

try {
  const response = await request
} catch (error) {
  if (reqo.isError(error) && error.code === 'E_CANCELED') {
    console.log('Request was canceled')
  }
}
```

### AbortController
```ts
// Or using AbortController
const controller = new AbortController()

// Start request
const promise = reqo.$get('/users', {
  signal: controller.signal
})

// Cancel after 1 second
setTimeout(() => controller.abort(), 1000)

try {
  const data = await promise
} catch (error) {
  if (reqo.isError(error) && error.code === 'E_CANCELED') {
    console.log('Request was canceled')
  }
}
```

## Error Handling
All errors returned by the library are instances of `RequestError`, which provides useful properties for debugging and logging.

```ts
import { reqo, errors } from '@outloud/reqo'

try {
  const data = await reqo.$get('/users/999')
} catch (error) {
  // Type-safe error checking
  if (reqo.isError(error)) {
    console.log('Status:', error.status)
    console.log('Code:', error.code)
    console.log('Message:', error.message)
    console.log('Response data:', error.data)
    console.log('URL:', error.config.url)
    console.log('Method:', error.config.method)
    console.log('Config:', error.config)
    console.log('Request:', error.request)
    console.log('Response:', error.response)

    console.log(error.toJSON()) // Serialize error to JSON, useful for logging
  }

  // Check specific error types
  if (error instanceof errors.TimeoutError) {
    console.log('Request timed out')
  }

  if (error instanceof errors.CanceledError) {
    console.log('Request was canceled')
  }
}
```

See [Error Handling](/guide/error-handling) for the full list of error properties.

## Type Safety

The library provides full TypeScript support:

```ts
interface User {
  id: number
  name: string
  email: string
}

interface CreateUserDto {
  name: string
  email: string
}

// Type the response
const user = await reqo.$get<User>('/users/1')
console.log(user) // User

// Type request and response
const newUser = await reqo.$post<User, CreateUserDto>('/users', {
  data: {
    name: 'John',
    email: 'john@example.com'
  }
})
console.log(newUser) // User
```

::tip
If you have an OpenAPI schema, use the [Schema Client](/guide/schema-client) to infer paths, parameters, bodies and responses automatically.
::
