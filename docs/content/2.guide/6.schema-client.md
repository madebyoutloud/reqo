---
title: Schema Client
description: Fully typed requests inferred from an OpenAPI schema.
---

The schema client wraps the regular client with types generated from an OpenAPI schema. Paths, path parameters, query parameters, request bodies and response data are all inferred — without writing a single generic.

Options follow the schema exactly: `params`, `query` and `data` are **required** when the operation requires them, **optional** when the operation marks them optional, and **rejected** when the operation defines none. The options argument itself may be omitted whenever nothing is required.

## Generating Types

Generate the TypeScript definitions from your OpenAPI document with [openapi-typescript](https://openapi-ts.dev/):

```bash
npx openapi-typescript ./openapi.yaml -o ./api.ts
```

This produces a `paths` interface describing every endpoint of your API.

## Creating a Client

Pass the generated `paths` interface to `createSchemaClient`:

```ts
import { createSchemaClient } from '@outloud/reqo'
import type { paths } from './api.js'

const api = createSchemaClient<paths>({
  url: 'https://api.example.com',
  headers: {
    'Authorization': 'Bearer token'
  }
})
```

::note
`createSchemaClient` accepts the same [client options](/guide/instances#options) as `createClient`.
::

## Making Requests

The client exposes the same [method shortcuts](/guide/basic-usage#method-shortcuts) as the regular client, but the `url` argument is restricted to the paths defined in your schema, and only to those that support the given method.

```ts
// Path is autocompleted and checked against the schema
const events = await api.$get('/special-events')
// events is typed as SpecialEventCollection

// Unknown paths are a type error
await api.$get('/unknown')
// ^ Argument of type '"/unknown"' is not assignable to ...

// So are methods the path does not support
await api.$post('/museum-hours')
// ^ Argument of type '"/museum-hours"' is not assignable to ...
```

### Path Parameters
Use the OpenAPI path template as the url and fill it with `params`. Keys are typed from the schema's `parameters.path`, and `params` is required whenever the path declares one.

```ts
const event = await api.$get('/special-events/{eventId}', {
  params: { eventId: 'dad4bce8-f5cb-4078-a211-995864315e39' }
})
// GET /special-events/dad4bce8-f5cb-4078-a211-995864315e39

// Forgetting them is a type error
await api.$get('/special-events/{eventId}')
// ^ Expected 2 arguments, but got 1.
```

### Query Parameters
`query` is typed from the schema's `parameters.query`. It stays optional as long as every query parameter is optional.

```ts
const events = await api.$get('/special-events', {
  query: {
    startDate: '2024-01-01',
    endDate: '2024-01-31',
    limit: 10
  }
})

// Operations without query parameters reject the option
await api.$get('/special-events/{eventId}', {
  params: { eventId: '123' },
  query: { page: 1 }
})
// ^ Type 'number' is not assignable to type 'never'.
```

### Request Body
`data` is typed from the operation's `requestBody`, and is required when the schema marks the body as required.

```ts
const event = await api.$post('/special-events', {
  data: {
    name: 'Mermaid Treasure Identification and Analysis',
    location: 'Under the seaaa 🦀 🎶 🌊.',
    eventDescription: 'Join us as we review and classify a rare collection.',
    dates: ['2023-09-05', '2023-09-08'],
    price: 30
  }
})
```

### Headers
`headers` accepts arbitrary values as on the regular client, but header parameters declared by the operation are suggested. They are never required, headers can also be set on the client or in a [hook](/guide/hooks).

```ts
await api.$get('/special-events', {
  headers: { 'Authorization': `Bearer ${token}` }
})
```

### Responses
Methods without the `$` prefix return the full `Response` object with a typed `data` property, exactly like the regular client. The data type is inferred from the operation's successful (`2xx`) response.

```ts
const response = await api.get('/special-events/{eventId}', {
  params: { eventId: '123' }
})

console.log(response.status)
console.log(response.data) // SpecialEvent
```

## Full Example

```ts
import { createSchemaClient } from '@outloud/reqo'
import type { paths } from './api.js'

const api = createSchemaClient<paths>({
  id: 'museum-api',
  url: 'https://api.example.com',
  retry: { limit: 2 }
})

api.on('request', (config) => {
  config.headers.set('Authorization', `Bearer ${getToken()}`)
})

// List events
const events = await api.$get('/special-events', {
  query: { limit: 10 }
})

// Create an event
const created = await api.$post('/special-events', {
  data: {
    name: 'Mermaid Treasure Identification and Analysis',
    location: 'Under the seaaa 🦀 🎶 🌊.',
    eventDescription: 'Join us as we review and classify a rare collection.',
    dates: ['2023-09-05'],
    price: 30
  }
})

// Delete it again
if (created.eventId) {
  await api.$delete('/special-events/{eventId}', {
    params: { eventId: created.eventId }
  })
}
```

## Extending the Client

`SchemaClient` is exported as a class, so it can be extended like the regular [Client](/guide/instances#client-class):

```ts
import { SchemaClient, type ClientOptions } from '@outloud/reqo'
import type { paths } from './api.js'

class MuseumApi extends SchemaClient<paths> {
  constructor(options: Partial<ClientOptions> = {}) {
    super({
      url: 'https://api.example.com',
      ...options
    })
  }

  getEvent(eventId: string) {
    return this.$get('/special-events/{eventId}', { params: { eventId } })
  }
}

const api = new MuseumApi()
const event = await api.getEvent('123')
```

## Typing Errors

`error.data` is untyped, because an error can be thrown before a response exists. Use `SchemaErrorData` to narrow it to the error responses (`4xx`, `5xx` and `default`) declared for an operation:

```ts
import { createSchemaClient, type SchemaErrorData } from '@outloud/reqo'
import type { paths } from './api.js'

try {
  await api.$get('/special-events')
} catch (error) {
  if (api.isError(error) && error.response) {
    const data = error.data as SchemaErrorData<paths, '/special-events', 'get'>
    console.error(data.title)
  }
}
```

`SchemaResponseData` does the same for successful responses, which is useful when passing schema data around:

```ts
import type { SchemaResponseData } from '@outloud/reqo'

type SpecialEvents = SchemaResponseData<paths, '/special-events', 'get'>

function render(events: SpecialEvents) {
  // ...
}
```

## Limitations

- Response data is inferred from every `2xx` status code (and `2XX`) declared by the operation. When an operation declares several, the data type is their union.
- When a response declares multiple media types, the data type is the union of all of them.
- Cookie parameters are not typed.
