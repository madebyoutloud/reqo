The library provides rich error types with detailed context about failed requests, making debugging and error handling straightforward.

## Error Types

All HTTP errors extend from `RequestError`:

```ts
import { errors } from '@outloud/reqo'

// Base error class
errors.RequestError

// Specific error types
errors.TimeoutError   // Request timed out, by `timeout`, `totalTimeout` or an `AbortSignal.timeout()` signal
errors.CanceledError  // Request was canceled, by `request.cancel()` or an aborted signal
```

## Error Kinds

Every `RequestError` has a `kind` that says what made the request fail, and a `code`:

| kind | code | when |
| --- | --- | --- |
| `http` | `E_HTTP` | the response has an error status, or `validate` rejected it |
| `timeout` | `E_TIMEOUT` | an attempt passed `timeout`, or the request passed `totalTimeout` |
| `network` | code of the cause, e.g. `ECONNREFUSED`, or `E_NETWORK` | no response, e.g. a refused connection or a failed DNS lookup |
| `canceled` | `E_CANCELED` | `request.cancel()` or an aborted signal |
| `parse` | `E_PARSE` | the body of a successful response could not be read, e.g. invalid JSON |
| `invalid` | `E_INVALID_REQUEST` | the request could not be built, e.g. a missing path parameter or a body that doesn't serialize; it is never sent |

```ts
if (reqo.isError(error)) {
  switch (error.kind) {
    case 'http': return `Server answered `
    case 'timeout': return 'The server took too long'
    case 'network': return 'Could not reach the server'
    case 'canceled': return
    default: throw error
  }
}
```

## Checking Errors

### Using isError Method

The recommended way to check for HTTP errors:

```ts
import { reqo } from '@outloud/reqo'

try {
  const data = await reqo.$get('/users/999')
} catch (error) {
  if (reqo.isError(error)) {
    // error is typed as RequestError
    console.log('Status:', error.status)
    console.log('Message:', error.message)
    console.log('URL:', error.config.url)
  }
}
```

### Using instanceof

Check for specific error types:

```ts
import { errors } from '@outloud/reqo'

try {
  const data = await reqo.$get('/users', { timeout: 1000 })
} catch (error) {
  if (error instanceof errors.TimeoutError) {
    console.log('Request timed out')
  } else if (error instanceof errors.CanceledError) {
    console.log('Request was canceled')
  } else if (error instanceof errors.RequestError) {
    console.log('Other request error:', error.status)
  }
}
```

## Error Properties

::note
Request details such as the URL, method and parameters live on `error.config`. They are no longer copied onto the error instance itself.
::

::field-group
  ::field{name="message" type="string"}
    Error message describing what went wrong.
    
    ```ts
    error.message  // 'Request failed with status code 404.'
    ```
  ::

  ::field{name="kind" type="'http' | 'timeout' | 'network' | 'canceled' | 'parse' | 'invalid'"}
    What made the request fail, see [Error Kinds](#error-kinds).
    
    ```ts
    error.kind  // 'http'
    ```
  ::

  ::field{name="status" type="number | undefined"}
    HTTP status code of the response, `undefined` if no response was received. Before reqo 2.4 it was `-1`.
    
    ```ts
    error.status  // 404, 500, undefined, etc.
    ```
  ::

  ::field{name="code" type="string"}
    Error code: `E_HTTP`, `E_TIMEOUT`, `E_CANCELED`, `E_PARSE`, `E_INVALID_REQUEST`, or the code of a network error, e.g. `ECONNREFUSED`, `E_NETWORK` when it has none.
    
    ```ts
    error.code  // 'E_HTTP', 'E_TIMEOUT', 'E_CANCELED', 'ECONNRESET'
    ```
  ::

  ::field{name="duration" type="number"}
    Duration of the whole request in milliseconds until it failed, including retries and the waits between them.
    
    ```ts
    error.duration  // 1520
    ```
  ::

  ::field{name="attempts" type="number"}
    Number of attempts made, `1` without retries, `0` when the request failed before the first attempt, e.g. in an `init` hook.
    
    ```ts
    error.attempts  // 3
    ```
  ::

  ::field{name="data" type="any"}
    Response body data if available. For a failed status whose body doesn't parse, e.g. an HTML error page sent as `application/json`, it's `undefined`, and the error is still the status error (`Request failed with status code 502.`), not a parse error.
    
    ```ts
    error.data  // { error: { message: 'Not found' } }
    ```
  ::

  ::field{name="config" type="RequestConfig"}
    Full request configuration (hidden from enumeration but accessible). This is where the request details live: client `id`, `name` and `meta`, `url`, `method`, `params`, `query`, `headers` and the rest of the request options.
    
    ```ts
    error.config.id      // 'github-api'
    error.config.name    // 'GitHub'
    error.config.url     // 'https://api.example.com/users/{id}'
    error.config.method  // 'GET'
    error.config.params  // { id: 999 }
    error.config.query   // { status: 'active' }
    error.config.headers
    error.config.timeout
    ```
  ::

  ::field{name="response" type="Response | undefined"}
    The Response object if one was received (hidden from enumeration).
    
    ```ts
    error.response?.headers
    error.response?.status
    ```
  ::

  ::field{name="cause" type="Error | undefined"}
    Original error that caused this error, e.g. a network error, the signal's reason for a `CanceledError` or `TimeoutError` caused by your own `signal`, or the previous attempt's error for a `TimeoutError` from `totalTimeout`.
    
    ```ts
    error.cause  // Original network error
    ```
  ::
::

## Logging Errors

Use `error.toLog()` to log a failed request. It returns plain JSON that is safe to log:

```ts
client.on('error', (error) => {
  logger.error(error.toLog(), 'request failed')
})
```

```json
{
  "client": "aml",
  "clientName": "AML service",
  "method": "POST",
  "url": "https://aml.example.com/checks/7?page=2&token=[REDACTED]",
  "params": { "id": 7 },
  "status": 422,
  "kind": "http",
  "code": "E_HTTP",
  "message": "Request failed with status code 422.",
  "duration": 312,
  "attempts": 1,
  "requestBody": { "name": "John", "password": "[REDACTED]", "file": "[File passport.pdf, 2.1 MB]" },
  "responseBody": { "error": "Invalid document" }
}
```

- headers are never included,
- values of sensitive keys are masked in the query, `params` and both bodies, at any depth. A key matches when it contains one of `password`, `token`, `secret`, `authorization`, `apiKey`, `api_key`, `access_token` or `refresh_token`, ignoring case, `-` and `_`,
- `File`, `Blob`, `Buffer`, `ArrayBuffer`, typed arrays and streams are replaced with a placeholder, also in `FormData`, which is logged as an object,
- each body is cut to 4096 characters of JSON, a longer one becomes a string ending with e.g. `… [truncated, 12.3 KB]`.

::field-group
  ::field{name="body" type="boolean"}
    Includes the request and response bodies. Defaults to `true`.
  ::

  ::field{name="maxLength" type="number | false"}
    Longest body in characters of JSON. Defaults to `4096`, `false` disables the limit.
  ::

  ::field{name="sensitiveKeys" type="(string | RegExp)[]"}
    Keys whose values are masked, replaces the defaults. A string matches a key that contains it, ignoring case, `-` and `_`, a RegExp is tested against the key as is.

    ```ts
    import { defaultSensitiveKeys } from '@outloud/reqo'

    error.toLog({ sensitiveKeys: [...defaultSensitiveKeys, 'iban', /^ssn$/] })
    ```
  ::
::

`error.toJSON()`, also used by `JSON.stringify(error)`, returns the same snapshot without the bodies.

### Sanitizing Other Values

The sanitizer behind `toLog()` is exported, to log other request data the same way, with the same options except `body`:

```ts
import { sanitize } from '@outloud/reqo'

sanitize({ email: 'a@b.com', password: 'secret', avatar: file })
// { email: 'a@b.com', password: '[REDACTED]', avatar: '[File avatar.png, 120.4 KB]' }
```

A string of JSON is parsed, so its keys are masked too.

## Status Code Handling

Handle different HTTP status codes:

```ts
try {
  const user = await reqo.$get('/users/123')
} catch (error) {
  if (!reqo.isError(error)) throw error
  
  switch (error.status) {
    case 400:
      console.error('Bad request:', error.data)
      break
    case 401:
      console.error('Unauthorized - please login')
      // Redirect to login
      break
    case 403:
      console.error('Forbidden - insufficient permissions')
      break
    case 404:
      console.error('User not found')
      break
    case 429:
      console.error('Rate limited - try again later')
      const retryAfter = error.response?.headers.get('Retry-After')
      console.log(`Retry after ${retryAfter} seconds`)
      break
    case 500:
    case 502:
    case 503:
      console.error('Server error - try again')
      break
    default:
      console.error('Unexpected error:', error.status)
  }
}
```

## Network Error Handling

Handle network-level errors:

```ts
try {
  const data = await reqo.$get('https://api.example.com/data')
} catch (error) {
  if (!reqo.isError(error)) throw error
  
  switch (error.code) {
    case 'ECONNREFUSED':
      console.error('Connection refused - server may be down')
      break
    case 'ETIMEDOUT':
      console.error('Connection timed out')
      break
    case 'ENOTFOUND':
      console.error('DNS lookup failed - check the URL')
      break
    case 'ECONNRESET':
      console.error('Connection reset by server')
      break
    case 'E_TIMEOUT':
      console.error('Request timeout exceeded')
      break
    case 'E_CANCELED':
      console.error('Request was canceled')
      break
    default:
      if (error.kind === 'network') {
        console.error('Network error:', error.message)
      }
  }
}
```

## Response Data Access

Handle API validation errors:

```ts
interface ValidationError {
  field: string
  message: string
}

interface ApiError {
  message: string
  errors?: ValidationError[]
}

try {
  await reqo.$post<User, CreateUserDto>('/users', {
    data: {
      name: '',
      email: 'invalid'
    }
  })
} catch (error) {
  if (reqo.isError(error) && error.status === 422) {
    const apiError = error.data as ApiError
    
    apiError.errors?.forEach((err) => {
      console.error(`${err.field}: ${err.message}`)
    })
  }
}
```

## Global Error Handler

Set up a global error handler:

```ts
import { createClient } from '@outloud/reqo'

const client = createClient({
  url: 'https://api.example.com'
})

client.on('error', (error) => {
  // Log all errors
  console.error('API Error:', {
    url: error.config.url,
    method: error.config.method,
    status: error.status,
    message: error.message
  })
  
  // Send to error tracking service, with a safe snapshot of the request
  if (error.kind !== 'canceled' && (error.status ?? 500) >= 500) {
    errorTracker.captureException(error, { extra: error.toLog() })
  }
  
  // Show user-friendly messages
  if (error.status === 401) {
    toast.error('Please log in to continue')
  } else if ((error.status ?? 500) >= 500) {
    toast.error('Server error. Please try again later.')
  }
})
```

## Best Practices

1. **Always check error types**: Use `reqo.isError()` or `instanceof` to type-check errors
2. **Handle specific status codes**: Provide user-friendly messages for common errors
3. **Log errors**: Send error details to monitoring services
4. **Log safely**: Use `error.toLog()` for logging. It never includes headers, masks sensitive keys and replaces files, but check `sensitiveKeys` covers the secrets of your API
5. **Don't swallow errors**: Re-throw unexpected errors
6. **Provide fallbacks**: Return cached data or defaults when appropriate
7. **User-friendly messages**: Transform technical errors into actionable messages
