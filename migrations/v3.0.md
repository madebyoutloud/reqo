# @outloud/reqo 3

Upgrades a project from reqo 2.x to 3. Most projects only need steps 1 to 4;
steps 7 and 8 are optional.

## Changes

- `RequestError.status` is `undefined` when there is no response, instead of
  `-1`. Its type is `number | undefined`.
- `RequestError.code` is `E_HTTP` for a failed status instead of an empty
  string, `E_NETWORK` for a network error without a code instead of an empty
  string, `E_PARSE` for a body that doesn't parse, and `E_INVALID_REQUEST` for
  a request that can't be built (a missing path parameter, an invalid URL, a
  body that doesn't serialize). `E_TIMEOUT`, `E_CANCELED` and network codes
  such as `ECONNREFUSED` are unchanged. A new `kind` says what failed:
  `'http' | 'timeout' | 'network' | 'canceled' | 'parse' | 'invalid'`.
- `RequestError.data`, the response body, is not enumerable, like `config` and
  `response`, so spreads, `console.log` and loggers leave the body out.
  `error.data` reads and assigns as before.
- Default messages name the client (`name`, else `id`) and the endpoint by
  its path template, never the filled-in URL or the query:

  | kind | 2.x | 3 |
  | --- | --- | --- |
  | `http` | `Request failed with status code 404.` | `AML service: GET /users/{id} failed with status 404.` |
  | `timeout` | `Request timed out.` | `AML service: GET /users/{id} timed out.` |
  | `canceled` | `Request was canceled.` | `AML service: GET /users/{id} was canceled.` |
  | `network` | `Request failed due to a network error.` | `AML service: GET /users/{id} failed due to a network error.` |

  Without a `name` or `id`, the prefix is left out. A request that can't be
  built rejects with its own message, such as
  `Missing value for path parameter "id".`
- `error.toJSON()` returns `client`, `clientName`, `method`, `url` (the full
  URL, with path parameters and query), `path` (the path template, e.g.
  `/users/{id}`), `status`, `kind`, `code` and `message`. It no longer has
  `params`, `query` and `data`. Headers are still never included.
- `responseType: 'auto'`, the default, returns a `Blob` for a content type that
  is neither JSON nor text, such as `application/pdf` or `image/png`, instead
  of `undefined`.
- The per-attempt `timeout` starts after the `request` hooks, so a hook that
  waits, such as a rate limit queue, no longer uses it up. `totalTimeout`
  still counts it. A `request` hook that rejects because the request was
  aborted makes the request reject with a `CanceledError` or `TimeoutError`.
- Requests return a `RequestPromise`, a `Promise` with `cancel(reason?)`,
  `timeout(ms)` and `safe()`, instead of a `Future` from `@outloud/future`,
  which reqo no longer depends on. `then`, `catch` and `finally` return a plain
  `Promise`, without `cancel()`. `result()` is a deprecated alias of `safe()`.
  `timeout(ms)` now rejects with a `TimeoutError` instead of a `CanceledError`.
- `createSchemaClient<paths>()` and `SchemaClient<paths>` are deprecated
  aliases of `createClient<paths>()` and `Client<paths>`.
- Request headers override client headers whatever the case of the name: a
  client `Authorization` and a request `authorization` now send the request's
  value, the client's was sent before.
- `headers`, of the client and of a request, also accept a `Headers` instance
  and `[name, value]` entries, which were silently dropped before.
- An object body with `content-type: application/x-www-form-urlencoded` is
  encoded as a form, e.g. `name=a+b`, instead of `name,a b`.

New, no change needed:

- `ClientOptions` `name`, `meta` and `plugins`, and `client.use(plugin)`.
- `config.id`, `config.name`, `config.meta`, `config.client` and
  `config.path` (the path template, e.g. `/users/{id}`) in hooks and on
  `error.config`. `RequestConfig.path` is required, so an object literal typed
  as `RequestConfig` needs it.
- `state.signal` in `request` hooks.
- `client.isOwnError(error)` and `isRequestError(error)`.
- The `rateLimit` plugin, from `@outloud/reqo/plugins/ratelimit`.

## Steps

Find the reqo clients first and change only code that handles their errors and
responses:

    grep -rnE '@outloud/reqo|createClient\(|createSchemaClient\(|new (Schema)?Client\b|extends (Schema)?Client\b' --include='*.ts' --include='*.tsx' --include='*.js' --include='*.mjs' --include='*.vue' --exclude-dir=node_modules .

A reqo error is a value narrowed by `isError()` or
`instanceof errors.RequestError`, a `catch` around a reqo call, or the argument
of an `error` hook.

### 1. Check for a missing response with `status === undefined` or `kind`

**Check:** `grep -rnE 'status\s*(===|!==|==|!=|<|<=)\s*-1|status\s*<\s*0|-1\s*(===|!==)\s*[a-zA-Z_.]*status' --include='*.ts' --include='*.tsx' --include='*.js' --include='*.mjs' --include='*.vue' --exclude-dir=node_modules .` and keep the reads on a reqo error, a hook's `state.error` or a retry `state.error`. Skip when none do.

Before:

    if (error.status === -1) {
      showOffline()
    }

After:

    if (error.kind === 'network' || error.kind === 'timeout') {
      showOffline()
    }

Use `error.status === undefined` to keep the exact meaning (no response,
including canceled and invalid requests). Comparisons such as
`error.status >= 500` no longer typecheck where the error is typed: use
`(error.status ?? 0) >= 500`, or check `kind` first. On an untyped error they
are silently `false` without a response, as they were with `-1`.

### 2. Replace checks for an empty `code`

**Check:** `grep -rnE "code\s*(===|!==|==|!=)\s*(''|\"\")|!\s*[a-zA-Z_.]*\.code\b|\.code\s*\?\?" --include='*.ts' --include='*.tsx' --include='*.js' --include='*.mjs' --include='*.vue' --exclude-dir=node_modules .` and keep the reads on a reqo error. Skip when none do.

An empty `code` meant an HTTP error, or a network error without a code. Every
error has a code now.

Before:

    if (!error.code) {
      return showServerError(error.status)
    }

    // in a retry validate
    return state.error.status >= 500 || state.error.code !== ''

After:

    if (error.kind === 'http') {
      return showServerError(error.status)
    }

    return (state.error.status ?? 0) >= 500 || state.error.kind === 'network'

A network error without a code now has `E_NETWORK`; it is still not retried
by default.

### 3. Read the response data from the error, not from `toJSON()` or a spread

**Check:** `grep -rnE 'toJSON\(\)|\.\.\.\s*(error|err|e)\b|Object\.(keys|entries|values|assign)\(\s*(error|err|e)\b|toMatchObject\(\s*\{[^}]*\bdata\s*:' --include='*.ts' --include='*.tsx' --include='*.js' --include='*.mjs' --include='*.vue' --exclude-dir=node_modules .` and keep the ones on a reqo error, plus snapshots or assertions of a serialized reqo error in tests. Skip when none are.

Before:

    const body = error.toJSON().data
    const { query, params } = error.toJSON()
    expect(error).toMatchObject({ status: 422, data: { errors: [] } })

After:

    const body = error.data
    const { query, params } = error.config
    expect(error).toMatchObject({ status: 422 })
    expect(error.data).toEqual({ errors: [] })

A log that needs the bodies adds `error.config.data` and `error.data` itself,
through the logger's redaction. Update test snapshots of `toJSON()` or
`JSON.stringify(error)` to the new fields.

### 4. Don't match on the message text

**Check:** `grep -rnE 'Request failed with status code|Request timed out|Request was canceled|Request failed due to a network error' --include='*.ts' --include='*.tsx' --include='*.js' --include='*.mjs' --include='*.vue' --exclude-dir=node_modules .`, plus `.message` comparisons and snapshots of reqo errors in tests. Skip when none are.

Before:

    if (error.message.startsWith('Request failed with status code 5')) retryLater()

    expect(error.message).toBe('Request timed out.')

After:

    if (error.kind === 'http' && (error.status ?? 0) >= 500) retryLater()

    expect(error.kind).toBe('timeout')

Branch on `kind`, `status` and `code`. Update snapshots of messages to the new
text.

### 5. Check `responseType: 'auto'` downloads

**Check:** `grep -rnE '\.\$?(get|post|put|patch|delete)(<[^(]*>)?\(' --include='*.ts' --include='*.tsx' --include='*.js' --include='*.mjs' --include='*.vue' --exclude-dir=node_modules .` and keep the reqo calls without `responseType` that reach endpoints answering a file, image or other binary content type. Skip when none do.

They resolved to `undefined` and now resolve to a `Blob`. Code that relied on
`undefined`, such as `if (data === undefined)` or a type `T` that is
`undefined`, must handle the `Blob`, or pass `responseType: false` to keep not
reading the body. A call that already passes `responseType: 'blob'` is
unchanged.

### 6. Replace `Future` with `RequestPromise`

**Check:** `grep -rnE "@outloud/future|\bFuture\b|\.result\(\)" --include='*.ts' --include='*.tsx' --include='*.js' --include='*.mjs' --include='*.vue' --exclude-dir=node_modules .` and keep the types and calls that hold a reqo request, plus `.cancel()` calls on a promise chained from one. Skip when none do.

Before:

    import type { Future } from '@outloud/future'

    function loadUsers(): Future<User[]> {
      return api.$get<User[]>('/users')
    }

    const names = api.$get<User[]>('/users').then((users) => users.map((user) => user.name))
    names.cancel()

    const [users, error] = await api.$get<User[]>('/users').result()

After:

    import type { RequestPromise } from '@outloud/reqo'

    function loadUsers(): RequestPromise<User[]> {
      return api.$get<User[]>('/users')
    }

    const request = api.$get<User[]>('/users')
    const names = request.then((users) => users.map((user) => user.name))
    request.cancel()

    const [users, error] = await api.$get<User[]>('/users').safe()

A promise chained with `then`, `catch` or `finally` no longer has `cancel()`:
cancel the request it came from. Keep `@outloud/future` in `package.json` only
if the project uses it for its own code; reqo no longer installs it.
`.timeout(ms)` on a request now rejects with a `TimeoutError` (`E_TIMEOUT`);
change code that expected `E_CANCELED` from it.

### 7. Optional: replace `createSchemaClient` and `SchemaClient`

**Check:** `grep -rnE '\b(createSchemaClient|SchemaClient)\b' --include='*.ts' --include='*.tsx' --include='*.js' --include='*.mjs' --include='*.vue' --exclude-dir=node_modules .`. Skip when nothing matches.

Before:

    import { createSchemaClient, SchemaClient } from '@outloud/reqo'

    const api = createSchemaClient<paths>({ url })
    class MuseumApi extends SchemaClient<paths> {}

After:

    import { createClient, Client } from '@outloud/reqo'

    const api = createClient<paths>({ url })
    class MuseumApi extends Client<paths> {}

A `Client` subclass that should also accept a schema becomes generic:
`class ApiClient<P = Untyped> extends Client<P>`, with `Untyped` imported from
`@outloud/reqo`. Inside it, call `this.request({ url, method })` instead of
`this.$get()`, whose type depends on `P`.

### 8. Optional: name the clients

**Check:** `grep -rnE 'createClient(<[^(]*>)?\(|new [A-Za-z]*Client(<[^(]*>)?\(' --include='*.ts' --include='*.tsx' --include='*.js' --include='*.mjs' --include='*.vue' --exclude-dir=node_modules .` and keep the reqo clients created without `name`. Skip when none are.

Give each client a `name`, such as
`createClient({ id: 'aml', name: 'AML service', url })`, so `error.toJSON()`,
logs and messages say which service failed.

## Verify

- `pnpm typecheck` passes.
- The searches of steps 1, 2 and 4 find no reqo error compared to `-1` or an
  empty code, and no old message text.
- No test snapshot of a serialized reqo error has `query`, `params` or `data`.
- No code imports `Future` from `@outloud/future` to type a reqo request.
- The project's tests pass.
